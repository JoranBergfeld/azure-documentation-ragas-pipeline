# 0001 — Per-chunk contextual decoration (Anthropic-style contextual retrieval)

**Status:** Accepted (2026-06-10)
**Spec:** `docs/superpowers/specs/2026-06-10-preprocessing-contextual-decoration-design.md`

## Context

The corpus is ~584 structurally similar MS Learn pages across ~199 Azure services.
Once chunked, fragments from different services are nearly indistinguishable
("What is X" / "Quickstart X" boilerplate), which produces *Document-Level Retrieval
Mismatch* (DRM): the retriever returns a plausible chunk from the wrong document.
Chunks need to carry their document identity into the index.

## Decision

Decorate every chunk with **chunk-specific situating context** generated by one LLM
call per chunk (full page markdown + chunk → 1–2 sentences, `temperature=0`), on top
of a deterministic heading breadcrumb. This is Anthropic's contextual-retrieval
recipe.

## Terminology note

The repo's `raptor_sac` mode, `raptor-sac` index, and any `SAC` shorthand in code
refer to the implemented per-chunk Anthropic Contextual Retrieval described in this
ADR's Decision. The **SAC** acronym in the rejected alternative below refers to the
distinct per-document situating technique from arXiv:2510.06999. They are not the
same thing.

## Alternatives rejected

- **SAC — one summary per document, prepended to all its chunks**
  (arXiv:2510.06999): ~5× cheaper (584 vs ~2,700 calls) and directly targets DRM,
  but per-chunk context subsumes it, and the published evidence is stronger for
  per-chunk: Anthropic measured a 35% reduction in top-20 retrieval failure from
  contextual embeddings alone, 49% combined with contextual BM25. Documented
  fallback if measured gains don't justify cost.
- **Breadcrumb-only (no LLM)**: kept as the deterministic floor and failure
  fallback, but a breadcrumb says *where* a chunk lives, not *what the page is
  about*, so it can't resolve lookalike confusion alone.
- **Late chunking** (arXiv:2409.04701): needs token-level embeddings;
  `text-embedding-3-small` on Azure OpenAI doesn't expose them. Infeasible here.
- **RAPTOR** (arXiv:2401.18059): hierarchical summary trees help cross-document
  synthesis; this corpus's Q&A is single-page. Disproportionate change.

## Consequences

- First full ingest pays ~2,700 LLM calls; re-ingests pay only for changed chunks
  (see ADR-0005). Azure OpenAI prompt caching amortizes the shared page-markdown
  prefix.
- If post-change measurement (ADR-0006) shows no gain on the hard test subsets,
  this ADR is revisited; per-document SAC and breadcrumb-only are the cheaper fallbacks.
